# Support

## Bugs

Use the repository's bug report form for reproducible software defects.

Before opening a report:

- search existing issues;
- use the latest supported version where practical;
- remove credentials, tokens and personal/sensitive data from logs;
- include exact versions and reproduction steps.

## Feature requests

Use the feature request form. Describe the problem first, then the proposed solution.

## Security issues

Do not use a public support or bug issue for a vulnerability. Follow `SECURITY.md` and use GitHub Private Vulnerability Reporting where enabled.

## Project-specific support

Individual Ashmere Software projects may publish their own support channels and service expectations. Those project-specific instructions take precedence over this organisation default.
